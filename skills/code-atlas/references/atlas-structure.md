# アトラスHTML 構造・デザイン規則

## 全体構造(単一HTML)

```
<header>
  システム名+一言説明
  データ取り扱いサマリー(保存場所/外部送信の有無)  ← 最重要情報。目立たせる
  監査バッジ(audit/があれば):「監査意見:稼働可|報告書 MEMO-…|2026-08-06|Codex独立監査」
</header>
<div class="layout">
  <nav>機能一覧(クリックで切替)+「全体像」</nav>
  <main>
    「全体像」: システム全体のデータフロー図(SVG)+主要フォルダ・ファイルの役割一覧
    各機能ページ: ①この機能は何か(2行) ②データフロー図(SVG・この機能分)
                 ③処理の流れ(ステップカード: 平易な説明+根拠チップ)
  </main>
</div>
<footer>「この文書について」: 生成日/対象コミットID/生成方法/整合性検証の方法と結果/
        「本書はAIが生成しコードとの対応を検証した文書です。根拠リンクにより人手で検証可能です」</footer>
```

## 根拠チップの動作

- `memo.py:44` のようなチップ。クリック(details/summary要素で実装、JSなしでも動く)で展開:
  - コード抜粋(3〜8行、等幅フォント、該当行をハイライト)
  - 「これは何をしているか」の平易な解説(1〜2文。専門用語を使う場合は括弧で説明)

## データフロー図(SVG)の描き方

- プラント系統図・配管図のイメージ:左から右へ「入口→処理→保存/出口」
- ノードは角丸矩形+日本語ラベル(例:「メモファイル(memos/)」「キーワード検索」「画面に表示」)
- 外部送信ノードは存在すれば赤系で強調。存在しなければ図の下に「外部への送信:なし(このシステムは完全にローカルで動作)」と明記
- 矢印にはデータの中身を添える(例:「メモ本文」)
- インラインSVGで生成。1機能あたりノード3〜6個に抑える(詳細はステップカードで)

## デザイン規則

- 外部依存ゼロ:システムフォント(font-family: -apple-system, "Hiragino Sans", "Yu Gothic UI", sans-serif)、CSS/JSはすべてインライン
- 配色はデジタル庁デザインシステム風の端正なトーン:本文 #1a1a1c、背景 #ffffff、アクセント #0017c1(青)、注意 #ec0000、成功系 #197a4b、罫線 #d8d8db
- 文字サイズ:本文16px、見出しは階層明確に。行間1.7
- 専門用語は初出時に括弧で平易な説明を付ける
- 印刷にも耐えるレイアウト(A4で崩れない)

## データの持ち方

- 生成時にコンテンツを直接HTMLに書く(ランタイムでのfetch禁止=file://で開けること)
- コード抜粋はHTMLエスケープを確実に行う
