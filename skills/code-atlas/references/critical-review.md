# critical-review モード — 急所の「検証読み」ビュー設計憲法

出所: 3社会議(Claude・Codex・Grok独立評価、2026-08-10)。詳細は ai-audit-research/critical5-council-synthesis.md。
目的: 非エンジニアが「全部を理解する」のではなく、事故のほぼ全てが通る少数の急所だけに能動的に目を通し、**具体的な許否(この挙動を私は許可したか)を自分で判断**できるようにする。code-atlas(全体地図)の姉妹ビュー。

## 大原則(theater=見せかけを避けるための憲法。破ったら作らない)

1. **「急所=全部」と表示しない。** found(発見結果)と coverage(解析範囲)を必ず分けて出す。未解析が1つでも残れば「全部確認した」と読める表現を禁止する。
2. **緑バッジ単独禁止。** 未解析・抽出失敗・未解決呼び出し・封印不一致・「不明」回答が1つでもあれば、総合結論を conditional / not-acceptable 側に倒す(ai-auditの結論ゲートと同型)。
3. **人間に許否を強制する。** 各急所は「候補 + 根拠行 + 人間の許可/禁止/不明の記録」が揃うまで未完了。眺めるだけで完了にしない。「不明」を潰さない(不明が残れば未検証)。
4. **未解決を隠さない。** 静的抽出が追えない箇所(下記の盲点)は「検出済み」と書かず、**赤で「判定不能候補」**として強制表示する。「見つからなかった=無い」と絶対に書かない。
5. **根拠を開かせる。** 各カードは根拠コード抜粋を開いて初めて許否を選べる(atlas根拠チップの強制開封版)。

## 検証する急所カテゴリ(会議で5→6点+横断に改訂)

| # | カテゴリ | 何を見るか | 候補発見の起点(例) |
|---|---|---|---|
| 1 | 外部への送信・出口 | 通信・ログ・テレメトリでデータが外へ出る点 | `http`/`urllib`/`requests`/`fetch`/`socket`/`smtp`/ログ送信 |
| 2 | 高影響な外部作用 | 削除・上書き・本番反映・課金・通知・権限付与・発注・機器制御 | `remove`/`unlink`/`rmtree`/`DELETE`/`DROP`/`charge`/`payout`/`deploy` |
| 3 | 機密・個人データのライフサイクル | 直書き・ログ+保存先・暗号化・保持期限・バックアップ・削除 | 秘密パターン/個人情報項目/保存先パス/暗号化有無 |
| 4 | 権限・認証の境界 | 関所が本当に閉じているか、素通りできないか | `auth`/`login`/`role`/`permission`/`@requires`/認可判定 |
| 5 | 異常時の安全動作・業務不変条件 | 入力異常・再送・同時実行・切断で二重課金/データ矛盾が起きないか | 入力検証・トランザクション・冪等性・排他制御 |
| 6 | 供給網の取り込み点 | 依存の実在・lock・既知CVE・slopsquatting・FFI/ネイティブ | 依存宣言・`import`・`ctypes`/`cffi`/native呼び出し |
| 横串 | 禁止事項(ネガティブ要件)の突合 | 仕様の禁止リスト各項目 ↔ 各カテゴリで違反がないか | 仕様書の禁止事項リスト全項目 |

補足: **設定・環境・CI/デプロイ経路**も対象(Replit型事故はソース行でなく実行文脈に出る)。ソースファイルだけを見ない。

## 抽出の頑健性と、原理的な盲点(隠さず開示する)

- Grep/パターンは**候補発見専用**。ラッパー1段で見逃す。第1版はこれを使うが「候補であり網羅ではない」と明記する。
- 将来強化: 言語別AST・コールグラフ・taint解析(入口→ラッパー→sink)、隔離環境での合成データ実行観測(通信プロキシ・偽DB・ファイル監視)で静的結果と突合。実装するまでは「未実施」と台帳に書く。誇張しない。
- **原理的に完全捕捉できない**(必ず赤で盲点表示する): `eval`/動的import/reflection/**ネイティブbinary・FFI(ctypes等)**/遠隔取得コード/難読化/未実行経路/行に出ない設定切替。
  一般の任意コードで「危険が存在しない」ことの完全証明は不可能。だから「盲点があること」自体を成果物に書く。

## 検証カードの構成(1急所=1カード)

各カードに次を必ず載せる:
- 操作契機(いつ起きるか) → 扱うデータ → 宛先/対象 → 発動条件 → 防護(ガード) → 静的根拠(`file:行`抜粋・要開封) → 実行証跡(あれば)
- 人間の回答: **許可 / 禁止(おかしい) / 不明** の三択(初期は未選択)。根拠抜粋を開くまで選択不可。
- カードは 要求ID・対象commit/hash・回答者・日時 に束ねる。対象が変われば回答を自動失効。

## カバレッジ台帳(完全性の担保・合格ゲート)

分母付きで「全ファイル・設定・依存・CI・生成物」を **解析済 / 未対応 / 除外** に分類して表で出す。未対応が残れば「全部」表示を禁止し総合を「判定不能」にする。ai-auditの requirements-matrix・未検証面台帳へ接続する。画面上部(バッジより上)に「抽出器名・既知盲点・未検証面・verify-seal結果」を固定表示する。verify-sealは「変更がない証明」に限定し、安全・完全性バッジに流用しない。

## 第1版の範囲(誇張しないための線引き)

第1版は静的HTMLで **候補抽出(Grep+AI分類)+カバレッジ台帳+検証カード+許否記録+盲点/未解決の赤表示** を実装する。**AST/taint/動的観測は「将来強化・未実施」と台帳に明記**し、第1版が網羅を主張しないことを憲法1で保証する。これを守れないなら作らない。
